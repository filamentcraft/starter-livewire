# FilamentCraft starter for Livewire

A Laravel app built with Livewire and Flux, where every team builds and publishes its own
website with [FilamentCraft](https://filamentcraft.dev).

The app has no Filament screens: sign-up, teams, settings, the website page and the inbox are
Livewire pages. FilamentCraft's visual editor opens full screen when you click **Edit**, and the
**All pages** link inside it brings you back to the app.

Built on the official Laravel Livewire starter kit (Laravel 13, Livewire 4, Flux, Fortify, teams)
and FilamentCraft 1.41.2 or newer.

The same app also exists for [React](https://github.com/filamentcraft/starter-react) and [Vue](https://github.com/filamentcraft/starter-vue).

## Before you start

- PHP 8.3+, Composer 2, Node 22+.
- A FilamentCraft license. The package comes from a private Composer registry, so setup asks
  for the email you bought it with and your license key.
  [Get a license](https://filamentcraft.dev/pricing).

## Install

```bash
composer setup
composer dev
```

`composer setup` checks your license, installs everything, creates a SQLite database and
seeds a user who belongs to two teams, each with a live website.

| Address                                    | What it is                                               |
| ------------------------------------------ | -------------------------------------------------------- |
| http://localhost:8000/login                | Sign in as `test@example.com` / `password`               |
| http://localhost:8000/{team}/website       | The team's website: pages, publishing, editor links      |
| http://localhost:8000/{team}/website/inbox | Messages from the website's contact and newsletter forms |
| http://localhost:8000/s/{team}             | The team's public website                                |

## How it fits together

FilamentCraft's editor is built on Filament, so `filament/filament` is installed. The kit
keeps Filament out of sight:

- **One editor-only panel.** `app/Providers/Filament/WebsiteEditorPanelProvider.php` was
  generated by `php artisan filamentcraft:install --standalone --owner="App\Models\Team"`. It
  extends FilamentCraft's `EditorPanelProvider`: the editor at `/builder` and nothing else, so
  any other `/builder` URL is a 404. It has no login page; signing in goes through Fortify like
  the rest of the app. Its `exitUrl()` points the editor's **All pages** link at the team's
  Website page.
- **Teams own websites.** `App\Models\Team` implements `SiteOwner` and uses `HasSite`, so each
  site's `owner` is a team, and the panel's `ownerModel()` makes `Team` its tenant.
- **One permission everywhere.** `TeamPermission::ManageWebsite` (owners and admins) is checked
  by `TeamPolicy::manageWebsite` on the Livewire pages. In the editor, `User` uses FilamentCraft's
  `HasWebsiteEditor` trait and returns those same teams from `editableWebsiteOwners()`. A member
  without the permission gets a 403 in the app and a 404 in the editor. One team can't open
  another team's pages.
- **Editor links.** The Livewire pages get their **Edit** links from `EditorUrl::to($site)` /
  `EditorUrl::to($page)`, built on the server.
- **Public sites.** `Route::filamentCraftTenant(Team::class)` in `routes/web.php` serves each
  live site at `/s/{team-slug}`. The `/s` prefix keeps team URLs (`/{team}/dashboard`)
  separate from public sites.
- **Stable addresses.** A team's slug is set once, when the team is created. Renaming the team
  keeps it, so the public site, shared links and editor URLs never change. (Laravel's kit
  regenerated the slug on rename.) Deleted teams keep their slug reserved, so a new team can
  never take over an old site's links.

New teams start with no website. The Website page asks for a style family and calls
`App\Actions\Website\CreateWebsite`, which provisions a live starter site through
`StarterSiteBlueprint::seed()`.

## Changing it

- **Who can edit.** Add or remove `TeamPermission::ManageWebsite` in `TeamRole::permissions()`.
- **Create a site on sign-up.** Call `CreateWebsite` from `App\Actions\Teams\CreateTeam`.
- **Custom domains or subdomains.** Set `filamentcraft.public_routes` to `true` and fill a
  site's `domain` or `subdomain`; see
  [public routing](https://filamentcraft.dev/guide/public-routing).
- **Your own sections, themes and blueprints.** Register them in `configureEditor()` of
  `WebsiteEditorPanelProvider`; see the [FilamentCraft docs](https://filamentcraft.dev/guide/getting-started).

## Removing FilamentCraft

```bash
php artisan filamentcraft:uninstall
```

It removes the panel provider, the published assets and the config, keeps your sites in the
database (add `--drop-tables` to delete them), and lists the files of this kit that still use
FilamentCraft.
